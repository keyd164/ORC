# KTV 消费账单智能识别与数据工作台 · 实施方案 V1.1

更新日期：2026-10-25。更新依据：用户明确最终成果为微信小程序，并要求完成小程序。

本版本是对 [完整方案 V1.0](plan-v1.0.md) 的修订。下列调整优先生效；未调整的字段、识别、数据留存、成本、备份与验收要求继续沿用 V1.0。原方案永久保留。

## 最终产品形态

最终日常操作端为一个微信原生小程序，首页分两个入口：

1. **账单采集**：业务日期、拍照、相册多图、预览删除、上传进度、逐张失败重试、识别详情与历史。
2. **数据管理**：账单筛选、中文字段修正、明确空值、置信度和原始 OCR 查看、人工复核、重复账单处理、异常列表、统计趋势、房间消费、支付方式及包厢类型分布、CSV/Excel 导出、完整备份。

原 PC 工作台保留为可选辅助工具，不作为日常使用前提，不再需要为了使用小程序启动网页服务。两端仍使用唯一一套后端、数据库和图片数据；不把 Vue 网页嵌入小程序。

## 小程序导航

共 9 个原生页面：首页、账单采集、上传记录、数据管理、账单查询、账单核对、异常处理、营业统计、设置与备份。

底部四项导航：首页、上传记录、数据管理、设置。拍照、核对、异常、图表等作为各入口的子页面。

连接地址在设置页填写并持久化保存，测试连接后使用。上传记录与识别中的详情仅在页面可见时每 5 秒刷新，离开停止；有未保存修正时不自动刷新覆盖。字段表单使用中文标签，金额单位元，空值需要显式保存。离开未保存表单时支持微信平台可用的离开提示。

## 重复账单处理

保留同日相同文件哈希去重。同账单号的不同照片首先进入疑似重复，均暂停统计。

人工可在账单详情指定同编号的原始账单：当前照片标记 excluded 并保留追溯；原始账单在没有其他未解决重复时恢复 none，但仍须已结且已复核才能统计。不允许自己关联自己、不同编号关联、循环或关联链。

允许撤销重复确认，恢复疑似重复与暂停入账；所有操作记录修改日志。修正账单号后自动失效不再匹配的重复关联。增加 `duplicate_links` 表，不删除原图或历史账单。

## 统计与导出

统计按归档日期；账单列表日期筛选按票面日期。仅已结、已复核、无重复争议的有效账单进入正式实收与分布。已确认排除的重复照片不计入待复核或疑似重复数量。

手机用条形视图展示每日实收趋势、上传/识别/复核/已结数量、房间账单数、实收、均单金额、消费分钟、支付方式与包厢类型分布。明确标注样本量。

账单筛选支持编号、房间、票面日期范围、复核状态、结算状态、实收金额范围；导出当前筛选或全部账单 CSV/Excel。Excel 可用平台文档查看器；CSV 和 ZIP 下载后由用户主动选择保存或处理。程序不自动向任何人发送文件。

备份由小程序触发后端创建、校验，再下载。整库恢复继续在电脑关闭后端后通过脚本执行，避免运行中替换数据库。

## 本地运行与验收边界

仍采用 Python + FastAPI + PaddleOCR + SQLite 免费本地方案。电脑运行后端并保存数据；手机连接电脑局域网地址，电脑需要开机。不开通云服务器、付费 OCR 或域名。

当前项目使用游客 AppID 供开发导入；微信实际 AppID、开发者登录、隐私声明配置、设备权限和网络调试由实际账号及设备环境完成。公开发布所需的平台网络要求单独评估，不作为已实现成果宣称。

验收分为：后端业务测试、小程序 JS 流程测试、WXML/WXSS 编译、开发者工具联调、真机与真实账单集验收。前三类通过不代表后两类已完成，真实 OCR 精度仍以标注图片测试集为准。
